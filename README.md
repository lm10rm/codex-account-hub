# Codex Account Hub

一个面向 Windows 的本地 Codex 多账号额度看板与安全切换工具。

无需来回退出登录，即可查看多个账号的剩余额度、重置时间和重置券；需要切换时，应用会先备份当前认证，再切换账号并重新启动 Codex。

## 功能

- 同时查看多个 Codex 账号的主要额度、周额度和重置时间。
- 当前账号自动置顶，并提供低额度颜色提示。
- 使用官方 Codex App Server 读取额度，不依赖网页抓取。
- 通过官方 Codex 登录页面添加或重新授权账号。
- 登录显示等待、验证和保存进度，保存前可以取消并清理临时认证。
- 一键切换账号并重新启动 Codex，也可选择仅切换。
- 分别显示账号切换和重启结果；重启失败可单独重试。
- 启动时检查中断的认证更新和临时凭据，显示恢复结果及重试入口。
- 支持账号重命名、单独刷新和删除。
- 当前账号重新授权后同步更新本机登录；认证文件缺失或损坏时可切换到已保存账号恢复。
- 窗口重新激活时仅核对本地账号，外部换号后才刷新额度；后台刷新前也会核对身份。
- 启动时立即展示上次成功额度，再在后台更新实时数据。
- 支持关闭、10、30 或 60 分钟自动刷新；托盘驻留期间仍然有效。
- 区分登录失效、超时、网络和本地文件异常，并提供重试或重新授权入口。
- 刷新失败保留缓存，超过 30 分钟的快照明确标注“数据陈旧”。
- 支持浅色与深色主题。
- 关闭窗口后驻留系统托盘，可从托盘刷新或重新打开；重复启动只会唤醒已有窗口。
- 使用 Windows DPAPI 加密保存认证信息。

## 安装

前往 [GitHub Releases](https://github.com/lm10rm/codex-account-hub/releases/latest) 下载最新的 Windows x64 安装包：

```text
Codex Account Hub_0.7.1_x64-setup.exe
```

安装包使用当前用户模式，不需要管理员权限。安装后可从桌面快捷方式或开始菜单启动，不会打开额外的终端窗口。

> 当前发布包尚未进行商业代码签名，Windows SmartScreen 可能显示未知发布者提示。请只从本仓库的 Releases 页面下载。

## 使用

1. 先在 Codex 桌面端或 CLI 中登录一个账号。
2. 打开 Codex Account Hub，点击“导入当前账号”。
3. 点击“添加账号”，在打开的官方页面中完成另一个账号的登录。
4. 应用会依次读取所有已保存账号的额度。
5. 点击“切换并重启”，确认后应用会保存当前账号、切换认证并重新打开 Codex。

切换会关闭正在运行的 Codex 窗口和任务，请先保存重要工作。

关闭主窗口后应用会继续驻留在 Windows 系统托盘。单击托盘图标可恢复窗口；右键菜单可刷新全部账号或真正退出应用。

自动刷新默认每 10 分钟执行一次，可在顶部改为 30 分钟、60 分钟或关闭。多个账号会依次刷新；自动失败会延迟后续重试，手动刷新始终可以立即执行。

重新授权当前账号后，应用会更新当前登录和保险库，但不会自动关闭正在运行的 Codex。请在方便时重启 Codex，使桌面端使用新授权。如果当前认证文件已经缺失或损坏，可直接从已保存账号选择“切换并重启”恢复使用。

升级会保留已有自动刷新设置；首次启动默认选择 10 分钟。

等待登录或验证账号时，可以点击“取消登录”；进入安全保存阶段后需等待完成。取消会结束本次登录进程并清理临时认证，浏览器中已打开的登录页面可自行关闭。

如果提示“账号已切换，Codex 重启未完成”，点击“重新启动 Codex”并确认即可，应用不会重复切换认证。异常退出后会在下次启动检查恢复记录；无法自动处理时保留相关文件，并提供“重试恢复”。恢复本身不会自动关闭 Codex。

登录取消、操作成功和恢复完成等普通提示会在 5 秒后自动消失；错误、进行中的登录和待重启提示保留，便于继续处理。拖动窗口或在账号未变化时重新激活窗口不会重新查询额度。

## 数据与安全

- OAuth 凭据仅保存在本机，并使用当前 Windows 用户的 DPAPI 加密。
- 应用不会要求或保存 OpenAI 账号密码。
- 额度读取由本机官方 Codex 进程完成。
- 不提供复制、导出或上传 token 的功能。
- 不会自动轮换账号，也不会绕过账号额度或公平使用限制。

完整说明见 [SECURITY.md](SECURITY.md)。

## 当前限制

- 仅支持 Windows x64。
- 每个账号目前只保留最近一次成功额度，不提供历史趋势图。
- 尚未提供开机启动和自动更新。
- 安装包尚未进行代码签名。
- Codex 桌面端或 App Server 协议升级后，可能需要同步适配。
