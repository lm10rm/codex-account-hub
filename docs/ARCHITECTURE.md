# 架构说明

Codex Account Hub 是一个完全运行在本机的 Tauri 桌面应用。React 负责界面，Rust 负责认证文件、加密、Codex App Server 通信和桌面进程管理。

## 数据流

```text
React 看板
    │ Tauri IPC
    ▼
Rust 本地核心
    ├─ Runtime discovery ── Codex CLI / Desktop
    ├─ App Server client ── account/read
    │                     └─ account/rateLimits/read
    ├─ DPAPI vault ─────── 加密账号副本
    └─ Account switch ──── 活动 auth.json + Codex 重启
```

应用不提供远程服务，也不把账号凭据发送给自建后端。

## Codex 发现

`runtime.rs` 负责寻找：

- Codex 可执行文件。
- 当前用户的 Codex Home。
- 可用的 Codex 版本信息。

桌面版升级后安装路径可能变化，因此运行时会重新发现路径，而不是把安装位置写死在界面代码中。

## 额度读取

`app_server.rs` 启动短生命周期的官方 Codex App Server，通过 JSON-RPC 完成初始化，然后读取：

- 当前账号的安全元数据。
- 主要和次要额度窗口。
- 使用比例和重置时间。
- 后端提供时的 reset credits。

返回界面的结构经过显式映射，不会把 App Server 的完整响应直接传给前端。

每份额度快照携带本地哈希账号 ID。查询前后会读取认证身份，如果期间账号变化或认证消失，丢弃本次结果并返回 `account_changed`，不写入额度缓存。保险库凭据加载和隔离查询回写时也会检查身份一致。

## 多账号隔离

每个已保存账号都有一个本地账号 ID。查看非当前账号额度时：

1. 从 DPAPI 保险库解密目标账号。
2. 在应用数据目录中准备独立 Codex Home。
3. 让官方 Codex App Server 在该目录内读取或刷新认证。
4. 读取额度。
5. 将更新后的认证重新加密。
6. 删除隔离目录中的明文 auth.json。

登录、导入、删除和切换等写操作由全局读写锁独占保护；额度读取共享读锁，并由信号量限制为最多 3 个并发任务。启动时先读取账号列表及当前身份、填充缓存，随后并行查询当前账号和其余账号。后台每轮刷新、单账号刷新和窗口重新获得焦点时会重新核对身份。

## 账号保险库

`vault.rs` 维护两类数据：

- `accounts.json`：账号别名、套餐等非敏感索引。
- `vault/<account-id>.dpapi`：由当前 Windows 用户 DPAPI 加密的完整认证载荷。

账号 ID 是稳定账号标识的 SHA-256 截断值，不保存完整账号 ID。索引和密文通过临时文件、同步落盘和 Windows 写穿替换提交。

## 账号切换

切换流程：

1. 当前认证有效且属于其他账号时，保存其加密副本；当前认证缺失或损坏时允许进入恢复流程。
2. 解密并验证目标账号。
3. 为当前认证生成额外的 DPAPI 回退备份。
4. 先写入包含原认证、目标身份和目标摘要的 DPAPI 事务记录，再使用 `MoveFileExW` 原子替换活动 auth.json。
5. 重新读取文件并验证账号身份。
6. 验证失败时恢复原认证。
7. 完成校验后清理事务记录；当前账号重新授权需等保险库也更新完成后再清理。
8. 用户选择“切换并重启”时，关闭 Codex 进程并从系统应用入口重新启动，检测到进程才报告启动成功。

回退备份最多保留最近 5 份。应用只替换认证文件，不修改 Codex 配置、会话、插件、技能或工作区数据。

恢复时若原认证损坏，仍将原始字节加密备份；读取被拒绝或其他 I/O 错误不会被当成文件缺失。目标凭据必须与所选账号一致。同一账号但授权内容不同也会更新主认证。写入前再次检查原文件是否变化，写入后的读取、解析及身份校验失败均尝试恢复原状态。该检查不能代替与外部 Codex 进程的跨进程事务锁。

账号切换结果和重启结果分开返回。`restart_codex` 只处理进程，不重写认证；前端二次确认后执行重试，避免把重启失败当成账号切换失败。

## 启动恢复

`recovery.rs` 在窗口开始加载前检查 `switch-transaction.dpapi`。原文件未变化时保留原登录；目标认证已生效时同步保险库并结束事务；出现其他有效登录时保留外部变更；主认证缺失或损坏且有有效原认证时尝试恢复。记录损坏、Home 不匹配或写入失败时保留记录并返回可重试提示，不阻止界面启动。

同时扫描应用自身的 `login/` 和 `runtime/` 下一级目录，清理已结束进程遗留的认证及已知临时文件。运行目录中刷新后的认证先加密写回，成功后才删除明文；失败时保留供重试。查询或登录进程 PID 写入 `hub-child.json`，进程仍在运行或无法确认状态时暂缓清理，不根据旧 PID 强制终止进程。检查拒绝链接和 Windows 重解析点。

恢复只覆盖本应用的认证事务与已知临时文件，不恢复任意 Codex 配置或会话；启动后恢复提示不会自动触发重启。

## 官方登录

添加和重新授权账号使用官方 `codex login`：

- 登录运行在独立 Codex Home。
- 用户只在官方页面完成认证。
- 应用不接收账号密码。
- 重新授权会验证登录身份与所选账号一致，不一致时取消覆盖。
- 如果授权完成时所选账号仍是当前账号，先备份并更新主认证，再更新保险库，避免主旧凭据随后覆盖新授权。返回结果明确标注是否更新当前登录，前端提示在方便时重启 Codex。
- 如果用户在外部切换到了另一个账号，只更新所选账号的保险库。主认证写入失败时不覆盖保险库；主认证更新成功但保险库保存失败时保留事务记录供恢复。
- `login.rs` 使用请求 ID 管理一次登录，事件区分排队、等待、验证、保存。取消入口不等待写锁，排队、登录和验证阶段可取消；保存阶段拒绝取消，避免中断提交。正常取消会结束并等待本次子进程退出，再清理临时认证。

## 前端状态

React 界面按账号 ID 保存本次运行中的最后成功额度及错误状态，包括当前账号首次读取失败。当前摘要只接受与当前账号 ID 一致的快照。当某次刷新失败时，账号卡继续展示旧快照并标记“缓存数据”；超过 30 分钟时追加“数据陈旧”。账号写操作完成时如果旧刷新尚未结束，会补排一次刷新。

Rust 后端把每个账号最近一次成功的 `UsageSnapshot` 原子写入 `usage-cache.json`。应用启动时，账号列表返回后先把缓存填入卡片，同时继续执行实时并行刷新；实时结果只会替换更旧的缓存。缓存损坏或写入失败不会阻断额度查询，也不会影响 DPAPI 账号保险库。缓存只包含脱敏邮箱、额度、重置时间和采集时间。

主题和自动刷新设置只保存外观枚举与刷新间隔数字，不包含账号信息。

窗口激活监听原生 `tauri://focus`，不使用会受标题栏拖动影响的 WebView `focus`。激活后只读取本地账号列表和当前身份，不启动 Codex 进程；只有当前账号 ID 变化时才刷新额度，同时合并进行中的重复检查。普通操作完成提示 5 秒后清除，错误和待处理状态保留。

旧版额度缓存缺少快照内的 `accountId` 时，从已有缓存键迁移；快照 ID 与缓存键不一致时丢弃该条目。首次无自动刷新设置时使用 10 分钟，已有的“关闭”设置继续保留。

## 后台刷新与错误状态

Rust 后端每 30 秒向前端发送一次轻量时钟事件，因此窗口隐藏到托盘后不依赖 WebView 的普通定时器。前端按用户选择的 10、30 或 60 分钟周期启动一轮后台刷新，并逐个账号串行查询。登录、切换、手动刷新或其他写操作进行中时，后台刷新会延后。

自动查询失败后按账号独立指数退避，最长 6 小时；登录失效的账号暂停自动重试，直到用户重新授权。手动刷新不读取退避状态。额度查询错误通过结构化错误码返回，界面可区分登录失效、超时、Codex 运行时、网络、App Server 和本地文件异常。

## 系统托盘与单实例

系统托盘由 Tauri 后端创建。关闭主窗口时后端拦截关闭事件并隐藏窗口；只有托盘菜单中的“退出”会结束进程。单击托盘图标或再次从快捷方式启动应用时，会恢复并聚焦已有窗口。

托盘“刷新全部账号”向 React 界面发送本地事件，复用与顶部按钮完全相同的并行刷新流程。当前账号名称只用于更新托盘菜单和提示文字，不新增账号凭据存储。
